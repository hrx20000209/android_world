# 02 任务条件检索与步级可用性（Stage B）

## 方法（`scripts/retrieval.py`）
- **任务级检索**：对其他模板的历史 goal 做 BM25（每个模板一篇文档）。查询词去掉停用词、app 名和数字，所以只有 app 名相同不会检索到记忆；没有正分就返回 `NO_APPLICABLE_MEMORY`。
- **相关性不用历史频率**：FULL3 已证明频率有幸存者偏差。改用**目标锚点**判断：当前指令里原样出现的 UI 标签（整词组）。
  - 一个导航槽位被"锚点授权"，当且仅当已有证据（历史结构或本次运行）显示它的后继页出现了当前页上没有的目标锚点。
  - 结构证据与任务无关，所以可以来自任何模板。
- **历史参数不算结构**：历史 episode 的后继页里，出现在该 episode 自己 goal 中的文字（事件标题、搜索词、文件名）是那个任务的运行时数据，要剔除。不剔除时，约 40% 的误授权来自这类泄漏，例如别的任务里的 "catch up on annual report"。
- **类别**：
  - 每个槽位：DIRECT / PARAMETERIZED / ENVIRONMENT_UNCERTAIN / ANCHOR1 / ANCHOR2 / UNKNOWN / INAPPLICABLE / UNSAFE；
  - DIRECT 的条件：当前页没有锚点，恰好一个安全槽位被证据显示能暴露新锚点，并且没有后继未知的安全槽位。

## 留一模板离线评测：BASE 两轮共 232 个 episode、2320 步
- 检索：0 次弃权，每个模板都能在同 app 的其他模板里找到相关词。检索延迟可以忽略：分类 p50 0.4 ms，p95 4.1 ms。

**模型实际点击的槽位按类别分布**

| 模型这一步点的槽位类别 | 步数 | 占全部步数 |
|---|---|---|
| 非点击（输入、滑动、STATUS 等） | 938 | 40% |
| UNSAFE（提交、对话框按钮、输入框、开关） | 576 | 25% |
| PARAMETERIZED（实体行或被 goal 点名的控件） | 439 | 19% |
| UNKNOWN（历史没有该边） | 121 | 5% |
| INAPPLICABLE | 100 | 4% |
| ANCHOR1 / ANCHOR2 / DIRECT / ENVIRONMENT_UNCERTAIN | 34 / 46 / 2 / 10 | 4% |

**图优先可以授权的导航决策（剔除历史参数之后）**

| | 只在成功的 episode 中 | 与模型实际动作一致 |
|---|---|---|
| DIRECT 直接触发 | 2 | 2 |
| 唯一锚点槽位，但被后继未知的槽位挡住（探索可以解决的情况） | 11 | 6 |

- 所有 episode 合计：DIRECT 4 次，被挡住 37 次，一致率 14 / 37（38%）。

## 补充：只用"被 goal 点名"做授权（不用图）
当页面上恰好有一个被 goal 点名、且之前没点过的控件时，模型下一步正好点它的比例：
- 安全控件：9 / 32（28%）；
- 实体行：14 / 43（33%）。
所以仅凭词面授权也不可靠：模型要在恰当的阶段才点它。

## 门 B：FAIL（可用性），检索本身可行
- 检索能找到同 app 的相关模板，不泄漏目标模板。
- 但在 AndroidWorld 上，能由图安全授权的导航决策只占全部步数的约 **0.6%**（13 / 2320，只算成功 episode），一致率约 **60%**。
- 模型的步骤主要是提交 / 对话框、参数化选择和输入，这些属于语义决策，按设计本来就该交给模型。
