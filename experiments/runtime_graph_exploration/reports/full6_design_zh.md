# FULL6 完整设计（待审阅，尚未启动）

## 一句话
图负责记住"做过什么、做了会怎样"；探索负责往图里补"没做过的会怎样"。用图的方式只有两种，**而且都必须先证明比模型自己更可靠**：
1. **替模型执行**：只执行有本任务授权的步骤；
2. **给模型提示**：只在提示的历史准确率高于模型自己时才注入。

## 1. 图（记忆）
| 组成 | 技术点 | 依据 |
|---|---|---|
| 不可变观测日志 | 每条记录：源状态 →（操作，参数）→ 后继状态；来源分 agent / 探索 / 系统执行；记录运行实例、episode 成败；冲突的后继全部保留 | 已实现，13046 条 |
| 状态身份 | 匹配用 activity + 骨架签名；落点验证只看 activity；剔除每条记录自己任务的参数文本 | 骨架签名再落点率 66%，activity 96%；不剔除时约 40% 的误授权来自参数泄漏 |
| 初始记忆 | 留一模板：只含其他模板的历史 episode，测试用新 seed 32 | 防泄漏 |
| 持续增长 | 运行中每个 episode 结束后，把它的观测（成功和失败都保留，并标注成败）追加进图，后续的**其他模板**可以使用 | 检验"图信息更多 → 提示更准"这个假设 |

## 2. 探索（推理窗口内，不调用模型）
| 技术点 | 规则 | 依据 / 风险 |
|---|---|---|
| 探什么 | 当前页上**图中还没有观测**的安全控件，按屏幕顺序；每个窗口 1 次，深度 1，不滚动 | 服务器窗口中位数 1.77 s，只放得下 1 次探测 |
| 安全 | 沿用 deny-list；跳过已知不可回滚的控件族（app 级记忆，跨任务生效）；跳过抽屉菜单项、原地改变内容的箭头类控件 | 前几轮回滚失败 26%；HLX 每个任务都有 1 次回滚失败 |
| 失败处理 | 回滚失败：停止本 episode 的探索，重新观测并重新请求模型 | 已实现 |
| 产出 | 子页面的标签和可点击项写入图（作为当前任务的运行时证据，任务结束后进入持久图） | 供后续的提示和推荐使用 |

## 3. 跳步：替模型执行，不调用模型
| 机制 | 授权来源 | 依据 |
|---|---|---|
| R3 实体流程复用 | 模型自己在本任务里刚示范过的流程。新增规则：同组实体必须在 goal 里以列表形式并列出现 | FULL5：触发的 9 个 episode 全部成功，调用 −19%；修掉了 MarkorMoveNote 的误触发 |
| 提交确认 | 模型上一步刚亲自点了提交，系统替它点随后的对话框按钮 | FULL5 中 SimpleCalendarDeleteEventsOnRelativeDay 的修复 |
| 跨任务跳步 | **不做** | 有幸存者偏差：导航跳步造成的损失是 7 vs 2 |

## 4. 提示：增强推理，注入 prompt
- **候选**：图推荐的下一元素：
  - 目标导向：某控件的子页出现 goal 原样点名的标签；
  - 历史轨迹：其他任务在这个页面最常点的元素。
- **校准门（新，原理性）**：实测模型基本照推荐做，所以注入的净效应 ≈ 推荐准确率 − 模型自身准确率。
  - 每个推荐都要先在图里做**留一任务**的回测：在其他任务的成功 episode 中，同一页面、同一来源的推荐有多少次正好就是下一步动作。得到准确率估计 p̂。
  - 只有 p̂ 的置信下界（Wilson）≥ 0.9（模型在这类状态上的实测准确率）才注入。
  - 门值来自实测，不是拍的。
- **模板**："The element most likely useful next is "X" at (x, y). <依据>"，同时说明可能出错。
- 高亮框不使用：模型对框几乎不响应（42 → 45）。

## 5. 实验（完整 AndroidWorld，116 个任务，seed 32，每组 1 次，串行）
| 组 | 内容 | 用来回答 |
|---|---|---|
| BASE | 纯 agent | 基线 |
| FULL6 | 1 + 2 + 3 + 4 全部 | 完整设计的成功率、步数、调用 |
| FULL6-noX | FULL6 去掉探索 | 探索的独立贡献（包括它带来的伤害） |

- **报告**：成功率与配对比较；两边都成功的任务上的步数和调用；跳步步数与错误跳步；提示的触发数、p̂ 分布、被采纳率与正确率；探测数、回滚失败、重新请求；**随着图增长，提示准确率是否上升**。
- **时间**：约 3 × 116 × 50 s ≈ 5 小时。

## 6. 预期与风险（按现有证据）
- 成功率大概率在 BASE ±5 以内：同一配置重复跑也能差 ±10。
- 省下的调用主要来自 R3 和提交确认，集中在多实体删除类任务。
- 校准门可能很少放行：前面的离线数据里找不到 p̂ > 0.9 且模型本身会错的子集。如果是这样，"提示"这一模块在完整运行中基本不触发，这本身就是一个结果。
- 探索预计有净伤害，FULL6-noX 会把它量化出来。
