# 图信息注入：截图高亮 vs 文字推荐（2026-10-14）

代码：`scripts/highlight.py`、`recommend.py`、`hl_offline.py`、`rec_offline.py`、`hl_run.py`、`hl_driver.sh`、`rec_driver.sh`
数据：`metrics/hl_offline.jsonl`、`metrics/rec_offline.jsonl`、`raw/hl/{BASE,HL,HLX,REC}/`

## 设计
- **图**：13046 条历史观测，按留一模板构建，探索得到的观测追加进本次 episode 的运行时证据。
- **选元素**（只读图，不调用模型）：
  - **目标导向**：某个安全控件的下一页出现 goal 原样点名、而当前页没有的标签；
  - **历史轨迹**（只用于文字推荐）：同 app 至少 2 个其他任务在这个页面上接下来点的元素，取最多的一个。
  - goal 点名的东西已经出现在当前页时，不给提示。
- **HL**：在截图上用红框标出元素，prompt 不变。**HLX** = HL，并且每个推理窗口探测 1 个未知的安全控件，验证回滚，把结果补进图。
- **REC**：截图不变，在 prompt 末尾加一段模板："The element most likely useful next is "X" at point (x, y). <依据>"，并声明它可能是错的。

## 结论
1. **高亮框几乎不改变模型行为**：点被框元素的次数 42 → 45，被改变的动作数量与安慰剂相当。
2. **文字推荐能有效左右模型**：照推荐点的比例从 35% 升到 55%；即使推荐的是无关元素，也从 9% 升到 33%。这说明"注入没用"不是因为模型不听，而是因为**推荐的内容不对**。
3. **瓶颈在推荐的准确度**：图推荐只有约 50% 正确，模型自己在这些状态上约 90% 正确。用更差的建议去左右更好的决策者，只会变差（改对 4 个、改错 14 个）。按支持度也找不到"推荐比模型更准"的子集：支持度越高，越集中在通用页面上，反而越不准。
4. 跨任务的图缺少"对这个任务该点什么"的信息，这和 FULL3 的幸存者偏差、oracle 试点的结论一致。能比模型更准的推荐，只来自本任务自己的证据：任务内的流程复用（FULL5），或模型刚授权的提交确认。这类信息直接替模型执行即可，不需要再注入 prompt。
