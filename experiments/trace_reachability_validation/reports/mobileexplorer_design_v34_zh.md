# MobileExplorer 设计（FULL33 / FULL34 版，10-20 整理）

一句话：**模型推理的同时在设备上做带回滚的探索，把推理轨迹和探索轨迹写进同一张在线构建的图；推理前先在图上找当前页面可执行的出边，找到就由图执行、省掉一次模型推理。** 全部在线完成：不需要离线执行同样的任务去收集轨迹。

---

## 1. 图

**节点**：页面，键为 (package, activity, layout 签名)。

**边**：(页面, 控件族) → 落地页面，附带元数据：
- 来源：agent（模型的推理轨迹）、explore（探索）、graph（图复用执行后写回）；
- 执行验证次数、误用次数（被模型撤销）；
- 目的页截图，用于读取目的页内容。

**构建**：本轮运行中逐步追加，跨任务持久。不读 profiling 图和历史轨迹。

**仍使用的离线统计**：只有统计量，不含任何轨迹。
- TF-IDF 的全局 IDF：以 app 为文档的词表；
- 任务侧 IDF：任务指令语料；
- 可回滚性的跨 app 角色先验。

---

## 2. 图复用 = 执行当前页面的一条出边

| 边类型 | 含义 | 图证据（触发依据） | 原来的机制名 |
|---|---|---|---|
| 启动边 LAUNCH | 桌面 → app 入口 | 本轮图上观测到进入该 app 的转移 | 跳过 app 启动 |
| 确认边 CONFIRM | 提交对话框 → 确认 | 本轮图上同一 app、同一页面观测到确认按钮转移 | 提交后自动确认 |
| 参数化边 PARAM | 入口页 →[导航/选值/输入]*→ 提交前页面，槽位绑定任务字段 | 本轮已完成、且模型自报完成的 episode 中抽取的过程（同模板留一） | 函数 |
| 模式边 PATTERN | 页面上带字段标签的空输入框，原地填入记录字段 | 页面结构本身：标签与记录字段匹配 | 表单 |
| 动作边 ACTION | (页面, 控件族) → 页面 | 本局重复出现的转移，或跨任务的边 | repeat 复用、导航宏 |

**统一触发条件**：前置条件成立 ∧ 图证据 ≥ 1 ∧ 能在实时屏幕上落地 ∧ 未被刹车。

**统一执行约定**：
- 停在提交前，提交由模型完成；
- 每次执行算一个计数步；
- 执行结果以 `[graph] ...` 的形式写入模型的动作历史。

**写回与刹车**：
- 每次执行都写回图，作为一条图执行边，增加该边的证据；
- 执行后模型的第一个动作若是撤销它（按返回，或启动后又打开别的 app），记一次误用；
- 误用次数 ≥ max(1, 成功次数) 时停用该边。

**冷启动**：图上还没有某条边时，由模型自己完成这一步；这一步作为 agent 边进入图，之后的任务即可复用。

## 3. 探索

### 3.1 时机与预算
- 在模型推理期间并行进行：每个推理窗口最多 5 次、最长 30 秒。
- 临时状态不探索：弹窗、键盘、菜单、选择模式、抽屉。FULL34 起，单窗口对话框也不探索。

### 3.2 候选
- 当前页面上图中尚未有该 (页面, 控件族) 边的安全控件，即页面级去重。
- 排除已学到会修改数据的控件和容器。
- 新建类入口（New / Add / +）在任务有待填记录时可以探索：它只打开编辑页，修改数据要等点保存。

### 3.3 打分

priority(c) = rel_TF-IDF(任务, 证据(c)) + λ·𝟙[相关性未知] − κ·(1 − P_rev(c))

**rel_TF-IDF**：任务向量与控件证据文本的余弦。
- 证据按图中已有的最强证据选择：已知边的目的页内容 > 同标签 / 同 resource-id 控件的目的页 > 控件自身文本。
- 词权重是三种 IDF 的几何平均：
  - 全局：以 app 为文档，留一；
  - 图局部：本 app 在图中的页面；
  - 任务局部：本局到达的页面。
- 列表行另加参数向量（实体名）的匹配。

**相关性未知项**（价值信息）：控件既无自身文本、也无图证据，或者是参数无法判定的实体行。相关性未知的控件排在"已知为 0"的控件之前。
- λ = κ(1 − 0.7)：未知控件当且仅当 P_rev ≥ 0.7 时值得探索。
- 离线依据：74% 的探索时刻所有候选的 TF-IDF 都是 0。此时子词、伪相关反馈、锚文本、目的页扩展都排不出有用控件（第一名有用率约 1%）；价值信息排序为 13–20%。

**κ(1 − P_rev)**：探索回不来时重新推理的期望代价，κ = 0.3。

只探索 priority > 0 的控件。门槛：发现类 P_rev ≥ 0.8，复核类 ≥ 0.7。

### 3.4 可回滚概率 P_rev（FULL34：分层贝叶斯）
- 第 1 层：控件角色 × 屏幕区域的跨 app 先验 p0。
- 第 2 层：本轮本 app 同类探索（发现类 / 复核类）的后验，μ = (s0·p0 + ok) / (s0 + n)，s0 = 10。
- 第 3 层：控件所在容器的证据，以 μ 为先验，强度 5。

离线依据：发现类探索的回滚失败率实测为 35%，复核类为 4%，原来的估计在发现类上偏高。分层后，失败多的 app 会自动收紧。

### 3.5 回滚与决策保全
- **回滚阶梯**：返回 / 重选 → 沿联合图的安全路径恢复 → 重启 app 并重放本局动作 → 内容核对。
- **决策保全**：探索结束后，如果屏幕和模型做决策时不同：
  - 差异不影响这个决策时，直接执行；
  - 被选控件只是位置变了时，在新位置执行；
  - 否则重新推理，记一次 requery，这是探索的主要代价。

## 4. 目标解析（参数化的基础）
- 表格、key: value 块、行内键值、引号、冒号后枚举、文件名、电话号码。
- FULL33 起：枚举只按逗号拆分，名字里的 and 不拆；时间中的冒号和问句不当作列表。

## 5. 结果（114/116 题，单轮，seed 30）

| 配置 | 成功 | 平均推理 | 成功任务推理 | 与 BASE 共同成功的推理 | 图复用 | 探索 | requery |
|---|---|---|---|---|---|---|---|
| BASE | 51 | 10.05 | 7.41 | – | 0 | 0 | 0 |
| FULL29（离线函数库） | 50 | 8.83 | 6.16 | 6.72→5.74（−15%） | 272 | 339 | 15 |
| FULL29X（无探索） | 48 | 8.62 | 6.65 | 7.03→6.35（−10%） | 264 | 0 | 0 |
| **FULL33（完全在线）** | 47 | 8.88 | 6.13 | 7.10→5.85（**−18%**） | 204 | 244 | 11 |
| FULL34（FULL33 + 分层 P_rev + 对话框门槛） | 运行中 | | | | | | |

FULL33 图复用按边类型：启动 75、确认 22、参数化 8、模式 67、动作 32（跨任务宏 6 + 本局重复 26），误用 0。

**可以写进论文的结论**
1. 完全在线、不用任何离线同任务轨迹，平均推理减少 12%；与 BASE 共同成功的题上减少 18%，与使用离线函数库的 FULL29 相当。
2. 关闭探索（FULL29X）后，与 BASE 共同成功的题上只减少 10%（FULL29 为 15%）。探索在成功任务上额外贡献约 5 个百分点；6 个带探索的轮次与 FULL29X 配对比较，4 轮更快。
3. 节省全部可按边类型归因。在线时，模式边（67 个字段）补上了离线参数化边（91 步 → 8 步）的大部分。

**局限（如实写）**
- 单轮成功率与 BASE 相差 0–5 题，处在同配置的波动范围内（±4 题）。不宣称提升成功率。
- 探索对平均推理的净效应受回滚失败抵消：失败导致 requery，主要落在失败任务上。FULL34 针对这一点。
- 在线参数化边触发很少：在线函数库有 18 个函数，但多数对不上入口页或字段名。这是下一步的提升空间。
- 零分时刻的价值信息排序，提升主要来自实体行；导航控件在零分时刻仍无法从文本识别。
