# Phase I 离线 Pilot 结论（决策门）

数据全部来自上一轮实验 `experiments/runtime_graph_study/raw/main` 的原始证据，没有新的设备执行。Pilot B 的模型调用使用 LabServer GELAB-ZERO-4B（8095，temperature 0）。

## Pilot A：历史轨迹能否预测 agent 下一步点什么

- **样本**：143 个 agent episode（干净参考 + 探索臂 + 无探索臂），共 533 次 agent 点击，覆盖 14 个任务、10 个 app。
- **可探测的点击**：只有 **276 次 (52%)** 的目标是 Explorer 允许探测的。其余是"保存 / 删除 / OK / 开关"等提交类控件，被安全规则排除。两种分母都报告了。
- **动作身份**：用 resource-id / class / desc / label 定义 slot；带 rid 的列表行折叠成"行族"（行文字是运行时数据）；不使用坐标。
- **防止泄漏**：只用评测 episode 开始之前的历史，加上本 episode 已经发生的步骤；图知识只用决策时刻之前的观测。

Top-1 覆盖率（分母为可探测点击 n=276；括号内为全部点击 n=533）：

| 历史设定 | 轮询 P0 | 旧 Explorer（未知优先） | 当前状态频率 P1 | 最长后缀 P2 | 变阶（支持度≥2）P3 | 轨迹+图前沿 P4 |
|---|---|---|---|---|---|---|
| warm（之前的所有运行） | 18.5% (9.6%) | 13.8% | **70.3%** (36.4%) | 71.0% | 58.3% | 67.7% |
| 跨任务（排除同任务模板） | 18.5% | 18.5% | **40.2%** | 39.9% | 38.0% | 40.2% |
| 跨 app（排除同 app） | 18.5% | 18.5% | 29.0% | 28.6% | 25.0% | 29.0% |
| 冷启动（只用本 episode） | 18.5% | — | 29.0% | 28.6% | 25.0% | 29.3% |

Top-3 覆盖：P0 50%，P1 86.6%（warm）。

**解读**
1. **轨迹能预测**：warm 设定下 top-1 覆盖率是轮询的 3.8 倍；跨任务（同 app 其他任务）仍有 40%。
2. **跨 app 的增益完全来自本 episode 内的重复**：跨 app 与冷启动数字完全相同（29%），说明不同 app 之间没有可迁移的轨迹信号。
3. **更长的历史几乎没有帮助**：P2 ≈ P1；加支持度门槛的 P3 反而更差（-12 点）。在这些数据上，"当前状态上 agent 过去选过什么"已经包含了几乎全部信号。按最长匹配阶数分层，有阶 0–2 的上下文时 top-1 达到 83–95%；完全没有匹配上下文的 72 个决策只有 26%。
4. **图前沿过滤（P4）的价值在于"新信息"**：agent 的下一步动作若此前从未被观测，且 P4 恰好排在第一，探测就能获得**新的、随后被 agent 用到的**转移。warm 设定下 P4 有 63 次，旧 Explorer 35 次，oracle 上限 126 次；跨任务设定下 P4 90 次，oracle 253 次。
5. **两跳**：在 98 对连续、可探测的点击中，第一跳和第二跳都排在第一的，warm P1 为 45 次，轮询 17 次；跨任务时为 24 次。
6. **行族假设**：同一屏同一行族里观测过不同行的 7 个行族中，6 个落到同一个目的布局。例外是 Markor 文件列表（文件夹和文件共用一个 rid）。

## Pilot B：子页面信息回传给父结点，能否改进决策

- **样本**：47 个决策状态，覆盖 12 个任务、8 个 app，标签由 Claude 人工核对（`configs/pilot_b_labels.json`）。分为：
  - **E**：原始运行中真实选错了元素，5 个；
  - **N**：Calendar 逐日翻页状态，8 个——方向正确但低效，原任务失败正是因为步数耗尽，而子页面证据里恰好有 "More options → Go to date"、"Change view → Monthly view"；
  - **C**：正确的对照状态，34 个。
- **记忆来源**：其他任务变体的观测，加本 episode 决策之前的观测（反事实代理，已标注）；不含成功标签和本运行的未来信息。29/47 个状态有已验证的两跳路径。
- **条件**：M0 无记忆；M1 一跳 UTG；M2 加子页面可点击项；M2P **安慰剂**（子页面列表错位挂到别的元素上，长度相同）；M2pre（M2 放在任务描述之前）；M3 深度 2 路径（区分已验证 / 组合）；M4 整个 app 的原始图。M0 重复一次（M0b）测噪声底：**0/47 改变**，即模型完全确定性，所有改变都由注入的文本引起。

| 条件 | 额外 token | 改变动作 | 纠正 | 弄错 | N 状态走捷径 |
|---|---|---|---|---|---|
| M1 一跳 | +172 | 7/40 | 1 | **4** | 0/8 |
| M2 子页面 | +341 | 5/40 | 1 | 2 | 0/8 |
| M2P 安慰剂 | +362 | 3/37 | 1 | 0 | 0/8 |
| M2pre | +342 | 9/40 | 2 | 3 | 0/8 |
| M3 深度 2 | +528 | 5/40 | 1 | 2 | 0/8 |
| M4 全图 | +920 | 7/47 | 0 | **5** | 0/8 |

**解读**
1. **没有任何记忆形式带来净收益**；纠正数 ≤ 弄错数。
2. **内容不起作用**：M1、M2、M2P、M3 在同一批状态上产生完全相同的改变（例如 pb2 四种条件都"纠正"、div4 都"弄错"）；安慰剂并不比真实子页面信息差。改变来自"多了一段文字"这一扰动，而不是信息本身。
3. **最有利的测试也失败了**：8 个 Calendar 状态的 M2 证据都明确写着 "Go to date / Monthly view"，模型仍然 0/8 采用捷径，继续逐日翻页。
4. **第二次点击是否必要**：在本模型上这个问题没有意义——一跳、子页面、两跳都没有用；深度 2 只增加 token（+528）。
5. **原始错误很少能复现**：E 集合中 M0 重跑时 4/5 已经是有效动作（原始运行用的是 PNG，这里用存档的 JPEG，可能有关），可以纠正的余地本来就很小。整个数据集中，有探索证据可用的状态上，真实"选错元素"的错误只有约 4 个；GELAB 的失败主要来自低效但有效的导航和文本编辑。

## 决策门

1. **Trace-Guided 选择是否优于简单基线？** 是，在离线数据上明确优于轮询（warm 3.8×，跨任务 2.2×）。
2. **Backward Reachability 证据是否改进 agent 决策？** 否。在 GELAB-4B 上所有注入形式都没有净收益，安慰剂对照显示内容不起作用。
3. **哪个失败了，为什么？** Reachability-as-prompt 失败：模型不使用 prompt 中的转移证据（与仓库此前"六种注入形式都没有效果、预填才有效"的结论一致）；而且有证据可用的状态上，可纠正的错误很少。
4. **是否值得做在线实验？** 结果为 **Candidate Outcome B**（Trace-Guided 正面、Reachability 负面）。只对 Trace-Guided 做小规模在线验证，回答：
   - 在线时，trace-guided 深度 2 探索能否在 agent 做出决定**之前**真正探到它将要点的动作；
   - 探到的结果能否在 **prompt 之外**被使用：预先观测动作结果，省掉动作后的观测时间、让下一次推理提前开始，或做执行前验证。

   不把 backward reachability 塞进 prompt。
