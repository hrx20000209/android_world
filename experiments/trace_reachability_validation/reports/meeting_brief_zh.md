# 组会简报：MobileExplorer 探索 → 图 → 推理 / 执行的验证（2026-10-13）

主模型为 GELAB-ZERO-4B（LabServer），环境为 AndroidWorld 本地模拟器。所有数字均为实测；标注"推算"的除外。

## 一句话结论
**页面转移跨运行非常稳定，任务只在少数几个页面上来回。真正能预测 agent 下一步的是"它自己以前的轨迹"，而不是探索建的图。探索证据交给模型看没有用（安慰剂对照）；用于执行侧（预填、预观测）能省 5–9% 的模型调用或约 1.4 s/次的观测时间，但在当前样本上看不出成功率差异，同一配置重复运行就相差 ±4/26。**

## 新增：同一 app 连续任务里，探索能否补上任务之间的空隙（离线，`analysis/xt_bridge/summary.json`）

**设定**：4 个 app × 各 2 个任务（Expense、Markor、Broccoli、Calendar），共 146 次可探测的 agent 点击。只允许使用**同 app 其他任务**的知识加本 episode 自己的过去。

**做法**：探索图提供"这个控件通向哪一页"。如果某个控件通向"其他任务的 agent 走过的页面"，就优先它（跨任务桥接）。另加一项确定性信号：控件文字是否原样出现在任务描述中。全部按字典序组合，不用加权分数。

**结果**（top-1 / top-3）：

| 策略 | 全部 (146) | 空隙页面：无跨任务轨迹 (72) | 有跨任务轨迹 (74) |
|---|---|---|---|
| 屏幕顺序 | 4.8% / 49% | 8.3% / 65% | 1.4% / 34% |
| 跨任务轨迹 | 42.5% / 72% | 8.3% / 65% | 75.7% / 78% |
| + 图桥接（图 = 决策前已有的边） | 43.2% / 75% | 8.3% / 65% | 77.0% / 85% |
| + 图桥接（图 = 探索覆盖整个 app，不含同任务 agent 的边） | **50.0% / 81%** | **23.6% / 79%** | 75.7% / 82% |
| 任务描述匹配 + 探索桥接 | 54.1% / 83% | **41.7% / 83%** | 66.2% / 82% |
| 按空隙切换（有轨迹用轨迹，否则用描述匹配 + 桥接） | **58.9%**（86/146，由上表计算） | 41.7% | 75.7% |

**解读**
- 同 app 跨任务时，**一半的点击落在没有跨任务轨迹的页面上**——这就是任务之间的空隙。
- 在空隙里，**只有当探索真正覆盖了这些页面的出边**，桥接才起作用：top-1 从 8% 升到 24%，与任务描述匹配结合后到 42%。
- 历史上实际探到的边（旧轮询探索、经常被中止）覆盖不足，所以没有收益：目标动作结果已知的只有 61/146。
- **结论**：连续建图有价值，前提是探索要**覆盖空隙页面**，而不是把力气花在已有轨迹的页面上。这给出一个清晰的设计：有跨任务轨迹的页面按轨迹排序（只做预观测）；空隙页面做覆盖式探索，用"通向已知工作流页面"来桥接。
- **待做**：在线验证（同 app 连续任务、空隙优先的探索）与闭环成功率；本结果是离线的，上界设定使用了所有运行的探索 probe。

## 可能被问到的问题
- **探索到底贡献了什么？** 在这批任务上：独立发现 <1%；验证 18 次预填只拒绝 1 次；冷启动下探索建的图不能替代轨迹（1/13 vs 9/14）。在线实测的正面收益是"按轨迹排序后的推测观测"（节省时间）；离线上，**同 app 连续任务中探索覆盖空隙页面后，跨任务桥接把空隙处的 top-1 从 8% 提到 24–42%**——这是探索在轨迹之外唯一测到的独立贡献，还需要在线验证。
- **为什么不把图给模型看？** 测了 6 种形式加安慰剂，内容不起作用。GELAB-4B 不使用转移证据（与之前"预填优于注入"的结论一致）。
- **阶段策略？** 开头深探没有数据支持；需要的是阶段消歧：续写上下文必须看到提交 / 结束等动作。
- **为什么成功率没有提升？** 预填只覆盖导航点击（约 10% 的步），提交、输入、列表行都交给模型；单次运行的成功率噪声约 ±4/26。

## 下一步（建议）
1. 端侧推理时延（约 10 s/次）下实测预填与推测观测的端到端收益——远端 1.9 s 窗口太短。
2. 成功率用 3 次以上重复，并改在 37 个波动任务上测。
3. 在线实现"空隙优先探索 + 跨任务桥接"：同 app 任务按顺序运行、连续建图，测命中率与成功率。
