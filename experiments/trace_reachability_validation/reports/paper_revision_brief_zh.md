## 1. 问题与动机（Motivation）

- **场景：** 移动 GUI agent（GELAB-ZERO-4B，vLLM 部署）在 AndroidWorld 上逐步决策，每步调用一次 VLM。
- **运行时动态：** 同一 app 的界面在运行时变化（首次启动引导页、弹窗、列表内容、标签页状态）。历史轨迹复用假设界面与历史一致，遇到运行时新状态就会失效。
- **受控证据（motivating example）：** Markor 首次启动引导页这一运行时新状态上：
  - 基于运行时探索 6/6 次越过；
  - 无记忆 BASE 1/6；
  - 历史轨迹复用 0/6。

  同一受控实验也表明，AndroidWorld 中大部分运行时变化是内容层面的，并不构成障碍。论文应强调"轨迹复用对运行时新状态无能为力，需要运行时获取的知识"，不应声称"运行时变化普遍阻碍 agent"。
- **跨任务的潜力（来自联合图分析）：** FULL21 中模型的 431 次跨页导航里，有 201 次（47%）走的边已被**其他任务**观测过，这些边的落地预测准确率 91–100%。图里的知识大量存在，关键在于怎么安全地利用。
- **核心思路：** 在运行时与 agent 并行探索界面，把 agent 自己的执行和探索观测统一组织成**运行时图**。图通过"直接执行、替代决策"减少 VLM 推理，同时为探索提供选择依据、安全约束和恢复路径。

## 2. 整体框架（Figure 1 新版结构）

一张图、两个循环：

1. **推理循环：** 截图 + 任务描述 → VLM agent → 设备执行。每步先检查图执行算子，能执行就不调用 VLM。
2. **探索循环：** 与每次 VLM 推理并行。每次推理最多 5 次只读探测，每次探测后恢复原状，观测写回图。
3. **运行时图：** 两个循环共享，在一个实验臂内跨任务持久化。
   - 屏幕层：页面节点 + 转移边，agent 边和探索边统一成联合图；
   - 过程层：参数化函数。
4. **图引导执行：** 每次推理前读图，能确定的步骤直接执行。
5. **决策保全：** 推理返回后，若探测改变了屏幕，先尝试保全模型的决策（有效性放行 / 重定位 / 恢复后执行），尽量不重新推理。

建议 Figure 1 中的连线：
- Agent → Exploration（"in parallel"）
- Exploration → Graph（写入边 + 可回退性证据）
- Device/Agent → Graph（虚线，agent 边）
- Graph → Execution → Device（跳过一次推理）
- Exploration → Decision preservation → Device

Figure 1 中应删除：
- "[Memory] Inject" 箭头；
- 顶部 Prompt 中的 [INFO] / [CAUTION]（最终设计不向 prompt 注入图信息）。

## 3. 技术细节（方法部分逐模块）

### 3.1 运行时图的构造（Graph Memory，回应批注 3）

**状态表示：多粒度签名。** a11y 树解析为 UI 状态，计算四级签名：
- `exact_sig`：全部节点，含位置；
- `struct_sig`：activity + 输入法状态 + 界面骨架 + 非列表的锚文本；
- `layout_sig`：activity + 输入法状态 + 骨架；
- `content_sig`：列表行文本、输入框内容、勾选状态。

不同用途用不同粒度：
- 页面身份用 (app, activity, layout_sig)，**不含内容**，列表多一行、时间戳变化不会产生新节点；
- "是否恢复原状"用 struct + content；
- 落地校验用 activity（实测 activity 级落地判断 96% 正确，layout 级 66%）。

**转移边与联合图。** 边 = (页面, 控件族) → 目的页面：
- 控件族 = 控件类别 + resource-id + 文本/描述，用来跨任务、跨内容匹配同一个控件；
- agent 边和探索边原本索引格式不同，联合图把两者统一到 (app, activity, layout) 页面和控件族上，同一张图里可以混合使用两种来源的边。

每条边记录：
- **来源（provenance）：** agent / explore，以及最早由谁发现；
- **可回退性证据：** 探测后 Back 能否恢复；
- **目的屏截图：** 用于不实际进入就能评估目的页内容（探索价值打分、函数入口判断）。

**容器级可回退性（跨任务学习）。**
- 控件角色由最近的具名父容器（标签栏、数字键盘、工具栏）表示；同一容器的控件共享返回栈行为，例如切换标签、按数字键都不能被 Back 撤销。
- 一个控件 Back 失败，整个容器记为不可回退，跨任务持久；通用容器（content / root 等）只记单个控件。

**副作用记忆。** 以下情况会把控件或容器记为"有副作用"，该 app 内以后不再探测：
- 恢复后屏幕回来了但内容变了；
- 探测改动了输入框内容。

**过程层：参数化函数。**
- 函数 = 入口屏 → [导航点击 | 按字段点选 | 按字段输入]* → **停在提交前**，提交由 agent 完成。
- **抽取：** 从成功轨迹逐步扫描，动作中出现的文本等于任务指令里某个值（表格、key: value、引号串、枚举、文件名、数字），就把这一步记为该字段的槽位；否则记为导航；遇到提交类控件就切分出一个函数。
- **复用：** 跨任务按模板留一（不用同模板的历史）；本局成功完成的子轨迹也会被抽成函数加入函数库。
- 完整性规则：≥2 个动作、≥1 个字段；多记录任务的函数必须覆盖每条记录都有的字段。
- **模式级表单函数：** 任务中的一条记录本身就是一个过程。屏幕上的空输入框标签（hint / resource-id / 上方说明文字）能与记录字段名对上时，就填入对应值。字段名做三种归一：
  - 去单位词（amount_dollars → amount）；
  - 连写匹配（preparationtime ↔ preparation_time）；
  - 记录的实体名字段只对 title / name 输入框。

  表单函数可在同一记录出现空字段的任何屏幕上重复触发，按（记录, 本屏空字段）去重，不覆盖已有内容。

**Figure 1 Graph Memory 面板建议画法：**
- 两张行数不同的列表截图指向同一页面节点，标注 "content-invariant page"；
- 边上标注 source / reversibility / capture，agent 边与探索边用不同线型但汇入同一张图；
- 过程层示例：`Click "+" → Type <name> → Type <amount> → Select <category> → (stop) → Save`，尖括号槽位用颜色标为"来自任务指令"，Save 改为灰色并标注 "left to agent"（不要打红叉）；
- 可选：标签栏整组标为 non-reversible 并跨任务继承。

### 3.2 在线探索策略（Online Exploration，回应批注 1）

**时机与预算：**
- 与每次 VLM 推理并行（推理中位数约 1.4 秒）；
- 每次推理最多 5 次探测，每个容器每个窗口最多探 1 次；
- 每次探测都完整恢复后，才开始下一次；
- 暂态页面（弹窗、对话框、输入法、选择模式、抽屉）上不探测，这些状态不在返回栈上。

**候选过滤（全部基于图）：**
1. **页面级去重：** (app, activity, 控件族) 的转移已在图中（不论来自 agent 还是探索、哪个任务）就不探。
2. **副作用排除：** 标签首词为操作动词的控件（Add to / Delete / Save / Send / Start / Lap / Play 等）、开关类控件、图中学到的副作用控件和容器，都不探。
3. **可回退性预测：** P(rev) 是 Beta 后验，只探 P(rev) ≥ 0.7 的控件；0.5–0.7 之间的控件只有在当前路径可重启重放时才探。
   - 先验：跨 app 的"角色 × 屏幕位置"可回退率，来自约 950 次历史探测：单个控件 78%，同类兄弟组 70%，带选中态的兄弟组（标签页）37%；
   - 证据：本 app 同一容器在图中的回退成功 / 失败次数，先验强度 5。
4. 列表行也纳入候选，但只有当行内容与任务参数值匹配时才有价值。

**价值打分：统一的图探索价值。** 相关性统一定义为 rel(goal, T) = 加权 TF-IDF 余弦（任务操作词向量 · 证据文本向量）。

- **任务侧：** 去掉 app 名、日期、数字、引号字面值、已解析的字段值后剩下的操作词和对象词，按出现与否计，权重为任务语料 IDF。
- **界面侧：** 词按出现次数累加，权重为全局界面 IDF（所有 app 的屏幕）与图中当前 app 页面局部 IDF 的几何平均。到处都有的词（More、Settings、本 app 工具栏）权重低。

按图中证据的强弱分层取证据文本 T：

| 层级 | 证据 | 估计价值 |
|---|---|---|
| L1 已知边 | 该边目的页内容；已知页面的价值沿图回传：V(页) = max(rel(页), 0.7 × 子页最大 V) | 0.8 × V + 0.2 × 自身文本 |
| L2 图中近邻 | 别处同标签 / 同 resource-id 控件所通向页面的平均 V | 0.5 × 平均 V + 0.5 × 自身文本 |
| L3 只有自身 | 控件标签 + resource-id 拆词 + 正上方说明文字 | 自身文本 |

例子（ExpenseAddSingle）：标签为 "Add expense" 的按钮只看自身文本时 rel = 0.45；而 "+" 按钮的目的页（Name / Amount / Category / Note 表单）rel = 0.83。图里有目的页证据时，即使是无文字的图标按钮也能得到高分。

**探测类型（每窗口按顺序填满预算）：**
1. **E1 预测下一步：** 按本任务记忆预测模型下一步会点的控件，提前打开；模型若确实选了它，就复用预观测的下一屏。
2. **FX 未知控件：** 通过过滤的未知控件，按价值取前若干个（P(rev) ≥ 0.7，每窗口最多 2 个）。
3. **D2 深一层：** 当前页没有未知控件时，沿一条探索验证过可被 Back 撤销、跨 activity 的已知边进入下一页，探那里价值最高的未知控件，再退回。选边得分 = 目的页 V + 内层控件得分 + 0.3 × 新颖度；同 activity 内的弹出菜单和对话框不能作为中间页；失败的边持久记录。
4. **RV 重新观测：** 本页已知、可被 Back 撤销、在**当前页面内容**下尚未观测过的边。信息单位是"边 + 页面内容"，用来刷新随任务变化的动态内容。实测 RV 的 Back 失败率只有 3%，FX 是 31%。

**恢复阶梯（从轻到重）：**
1. 原地内容变化 → 再点一次；
2. 切换了标签 → 重新选中原标签；
3. 新页面 → Back（最多 2 次，第二次只在第一次 Back 仅关闭了输入法时才按）；
4. 沿探索边恢复（≤2 跳）；
5. 联合图安全路径恢复（≤3 跳）；
6. **重启加重放：** 强制停止 app → 重新启动 → 按本 episode 自启动以来记录的动作路径重放。前提是路径不含提交，且不超过 12 步。
7. 内容校验：恢复后内容变了，就把该控件学为副作用。

Back 失败的控件所在容器被学为不可回退（见 3.1）。

### 3.3 图引导执行与决策保全（Graph-guided Execution，回应批注 2）

**原则：图用来"去掉决策"，而不是"给模型加信息"。** 每个执行算子都满足两个条件：
1. **落地：** 在当前实时屏幕上找得到要操作的控件或字段；
2. **停在提交前：** 提交类动作永远由 agent 自己做。

条件不满足就交给 VLM。

**为什么不注入：** 消融中，六种把图信息注入 prompt 的形式（文本提示、高亮等）对成功率和步数均无显著作用，而直接替代决策在步数上有显著收益（3.4σ）。图给出的"下一步提示"正确率约 50%，模型自己约 90%，而模型又倾向于服从文本提示，所以注入是净负收益。

**执行算子（统一视为"函数应用"：每次推理前检查入口条件和参数绑定，成立就不经模型执行，计 1 步）：**

| 算子 | 入口条件 | 参数 | 每轮触发（FULL21） |
|---|---|---|---|
| `open_app`（启动折叠） | 桌面 | 任务中的 app 名（限图中见过的包） | 94 次，不计步 |
| `confirm`（提交确认） | 模型自己提交后弹出的纯确认对话框 | 无 | 约 23 次 |
| `fill_record`（库函数） | 函数首步在当前屏落地 | 当前记录的字段值 | 约 28 次，约 87 个动作 |
| `form`（表单函数） | 本屏有与记录字段名匹配的空输入框 | 当前记录的字段值 | 约 9 次，27 个字段 |
| `graph_reuse`（本局复用） | 本局在同一页面上模型两次选择同一安全导航控件，且落地一致、离开了本页 | 无 | 7–14 次 |

- 多记录任务：一条记录在被处理过之后、模型提交时才算完成，然后"当前记录"前进到下一条，算子会再次触发。
- 本局复用只针对离开当前页面的重复转移。页内重复（翻月、数字键）交还模型；模型撤销就立即刹车。
- 执行的每个动作以 `[graph] Typed "..."` 的形式写入模型的动作历史，模型知道这些步骤已经做过。

**决策保全（探测后避免重新推理）：** 推理与探测并行，推理返回时屏幕可能已被探测改变，按顺序处理：
1. **决策有效性放行：** 同 activity、同布局，且模型所选坐标处仍是同一控件 → 直接执行；
2. **决策重定位：** 同 activity，模型所选控件（控件族 + 标签）在当前屏上唯一存在 → 把动作移到它的新位置执行；
3. **恢复后执行（FULL22，运行中）：** 状态不符时先用联合图 / 重启重放恢复，恢复成功则执行原决定，否则放弃该决定，下一步重新决策；
4. 以上都不行 → 重新推理。

FULL21 中重定位 8 次、放行 8 次，重新推理从 43 次降到 33 次，未发现误点。

**独立模块（不属于主算法）：**
- 首次启动引导页：单独处理；
- 卡住：同一导航控件连续 3 次无效 → 系统 Back，不注入任何内容；
- 环境漂移：每局开始时把默认短信应用角色重置回基准短信 app。

## 4. 建议的贡献点表述（3 条）

1. **以执行替代决策的运行时图复用：** 把 agent 执行与在线探索统一成跨任务持久的联合图。把启动、提交确认、绑定任务字段的参数化函数、表单填写和本局重复导航都表示为"入口条件 + 参数绑定"的函数应用，能落地时直接执行，替代 VLM 决策。
2. **图引导的安全在线探索：** 探索与推理并行。图决定哪些控件值得探：页面级去重，以及按图中证据分层的 TF-IDF 价值（目的页 > 图中近邻 > 自身文本），并沿图回传。图也决定哪些控件探了会回不来：暂态门控、副作用排除、角色先验与容器证据的可回退性预测、容器级跨任务学习。
3. **基于图的恢复与决策保全：** 多级恢复阶梯（含沿图路径恢复和重启重放）；探测后通过有效性放行和决策重定位保全模型的决策，使探索几乎不增加推理调用。

## 5. 实验设置与计步口径

- **基准：** AndroidWorld，114 个任务（排除 4B_2 中出错的任务），seed 30；主配置跑两轮同配置重复。
- **模型：** GELAB-ZERO-4B，所有臂同一模型、同一系统提示。
- **对比：**
  - 4B_2：已有的 4B 基线结果文件；
  - BASE：同一环境、同一 agent，不使用图和探索。
- **计步：** 推理步数 = VLM 调用次数（含重新推理）。一次图执行（无论几个动作）计 1 步；启动折叠在推理之前完成，不计步。4B_2 的 episode 长度本身就是推理步数。
- **噪声：** 同配置单轮成功数波动约 ±10 题。主指标是"双方都成功任务上的配对推理次数"和机制读数，成功率需多轮合并报告。

## 6. 实验结果

### 6.1 主结果（推荐用 FULL21 两轮合计）

| 配置 | 成功 | 平均推理步数 | 成功任务平均推理步数 | 配对 vs BASE（双方都成功） |
|---|---|---|---|---|
| 4B_2 | 54/114 (47.4%) | 10.75 | 7.85 | – |
| BASE | 51/114 (44.7%) | 10.05 | 7.41 | – |
| FULL21 第 1 轮 | 52/114 | 9.38 | 6.31 | 6.63 → 6.18（21 快 / 7 慢） |
| FULL21 第 2 轮 | 49/114 | 9.18 | 6.16 | 6.45 → 6.11（20 快 / 10 慢） |
| **FULL21 两轮合计** | **101/228 (44.3%)** | **9.28** | **6.24** | 两轮均 20+ 快 / ≤10 慢 |

结论表述：
- **推理步数：** 平均 9.28 vs BASE 10.05（−7.7%）；成功任务 6.24 vs 7.41（−16%）。
- **成功率：** 44.3% vs BASE 44.7%，持平。

### 6.2 设计演进（消融式的逐步增量，均为单轮）

| 配置 | 增量 | 成功 | 平均推理步数 | 成功任务推理步数 |
|---|---|---|---|---|
| FULL8 | 启动折叠 + 提交确认 | 53 | 9.43 | 7.55 |
| FULL12 | + 函数图、FX 探索、重启重放恢复、决策有效性放行、副作用排除 | 56 | 9.43 | 7.05 |
| FULL16 | + 图感知探索（去重、可回退性预测、容器学习、D2）+ 统一图价值 | 49 | 9.66 | 6.14 |
| FULL17 | + 每推理最多 5 次探测、RV、联合图恢复与路由 | 49 | 9.95 | 6.88 |
| FULL18 | + 本局复用、可重复触发的表单函数 | 51 | 9.30 | 6.73 |
| FULL19（两轮） | 复用只针对离开本页的重复 | 96/228 | 9.43 | 6.41 |

| 机制 | 次数 |
|---|---|
| open_app | 94 |
| confirm | ~23 |

### 6.4 探索读数

**来源 × 结果矩阵（模型的跨页导航动作）：**

| 配置 | 导航动作 | 仅 agent 边（落地准确率） | 仅探索边（准确率） | 两者（准确率） | 落地页最早由探索发现 |
|---|---|---|---|---|---|
| FULL12 | 622 | 309（91%） | 8（88%） | 32（100%） | 17% |
| FULL17 | 688 | 345（92%） | 15（93%） | 29（97%） | 24% |
| FULL21 | 431 次跨页导航 | – | 13（100%） | 32（94%） | 24% |

**其他读数：**
- **探索排序的有效性：** FX 选中的控件后来被模型点击的比例，从旧排序（FULL12）的 4.7% 升到统一图价值（FULL16）的 12.8%。使用图近邻证据（L2）时，91% 的候选有非零相关性；只靠自身文本（L3）时只有 28%。
- **恢复阶梯（FULL17）：**
  - Back 失败率 15%；
  - 重启重放恢复 51 次成功、17 次失败；
  - 联合图路径恢复 9/82 次成功（Back 失败后多半已离开 app，图中没有回原页的边）。
- **探测量与代价：** 加大探索量（FULL17，每次推理 0.6 次探测）让探索发现的落地页比例从 8% 升到 24%，但重新推理从 30 次升到 47 次。之后靠决策重定位等机制，把重新推理降回约 32 次。
- **重新推理的来源（FULL19 两轮，92 次）：** 37 次时设备已离开 app，41 次同 activity 但布局变了，13 次布局相同。

## 7. 可以写 / 不能写的结论

**可以写（证据充分）：**
- 在成功率持平（44.3% vs 44.7%，两轮）的前提下，平均推理步数降低 7.7%，成功任务推理步数降低 16%，两轮配对比较均以 20+ 对 ≤10 占优。
- 图的收益来自"执行替代决策"（约 17.6% 的决策由图执行），而不是 prompt 注入；注入类方式在消融中无显著作用。
- 图引导的探索更有针对性：探索选中控件被模型后续点击的比例从 4.7% 升到 12.8%；探索边的落地预测与 agent 边一样准确（93–100%）；模型落地页中约 24% 最早由探索发现。
- 安全约束、恢复阶梯和决策保全显著压低了探索代价：重新推理约占 3% 的决策；决策重定位使重新推理从 43 次降到 33 次。
- 运行时新状态（如首次引导页）上，轨迹复用失败而运行时探索有效（受控实验 6/6 vs 0/6）。

**不能写（目前没有证据或在噪声内）：**
- "探索直接提升了成功率"：成功率持平；探索知识主要以"不增加代价的图知识"形式存在，直接转化为跳过推理的仍是函数和复用。
- "图实现了跨任务的多步导航复用"：47% 的模型导航边已在图中，但这些步仍由模型推理；联合图路由每轮 ≤3 次，执行后函数落地 0 次。这是**局限和未来工作**，不是贡献。
- "注入探索结果让模型推理更准确"：与实验证据相反。
- "运行时变化普遍阻碍 agent"。
- 不要把任何单轮的成功数差异（例如 FULL12 的 56）写成显著提升。

## 8. 局限（建议写进论文的讨论部分）

1. 省下的推理几乎全部来自过程级复用（函数、表单、确认、启动）。图中大量可靠的导航边没有被直接执行：边上只有可达性，没有"对哪类目标有用"的语义。
2. 函数覆盖约 20/114 个任务，受限于字段名的精确匹配和同 app 历史的存在。
3. 状态身份：layout 签名会随内容碎片化，activity 又过粗；隐藏上下文（当前文件夹、当前选中日期）不在状态里，这是复用翻过头、路由误入的根因。
4. 探索作用以间接为主（扩充图、提供恢复路径和入口），加大探索量只增加代价。
5. 改进方向见 `mobileexplorer_design_review_zh.md` 的 B–D 节：在边上累积"目的页打开了什么"（探索提供）和"曾服务于哪类目标"（成功执行提供）两类证据，做目标条件化的多步导航宏，并在参数动作和提交处截断。离线：最有把握的 20% 候选上准确率 88%。
