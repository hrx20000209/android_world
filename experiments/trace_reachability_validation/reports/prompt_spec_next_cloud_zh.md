# 云端任务：验证"推测式提前运行下一次推理"（speculative next inference）

全程用中文汇报。每跑完一题汇报一次：成功率、推理次数、成功任务的推理次数、端到端时延。不要停下来等我回复。

## 背景

- **项目**：MobileExplorer，一个在 AndroidWorld 上运行的 GUI agent，目标是投 MobiCom / MobiSys / SenSys。
- **决策模型**：GELab-Zero-4B（OpenAI 兼容的 vLLM 接口）。
- **代码位置**：`experiments/trace_reachability_validation/`；主入口 `scripts/full_run.py`；对比实验驱动 `scripts/e2e_driver.py`。
- **已实现的流式提前执行**（arm FULL41 / FULL42，`STREAM_ACT=1`）：
  - 模型输出格式为 `[<THINK>…</THINK>] explain:… action:… point:x,y … summary:…`，summary 在最后。
  - 决策以流式接收；一出现 `summary:` 键，就说明动作字段已经完整，立刻执行动作并观测下一屏，summary 在后台继续生成，下一次推理前再补进历史。
  - 在 Orin 上，动作字段比整条输出提前约 3.5 秒完成。流式提前执行把每步"推理之外的时间"从 3.3 秒降到 0.5 秒，端到端快约 16%。
  - 实现见 `full_run.py` 中的 `_stream_call`、`_decide_stream`、`_commit_stream`、`_resolve_pending`。
- **还剩下的关键路径**：动作字段出来 → 执行 → 等界面稳定、截图 → 等 summary 生成完（剩余约 1 秒）→ 下一次推理（prefill 约 4.5 秒 + 生成，单次约 17 秒）。

## 要验证的想法

当前推理的动作字段出来后，如果图里能找到"当前页面 + 这个动作 → 目的页面"，就不必等动作执行完、也不必等 summary，直接用这个状态**立刻开始下一次推理**；前台同时执行动作，进入这个状态。设备确实落在预测页面上，就采用推测结果；否则丢弃，正常推理。

## 已有的离线结果（`scripts/spec_next_offline.py`，在 FULL40 的历史轨迹上）

- **覆盖率**：动作的目的地在图里有确定记录和截图的，约占 33%（120/368 次元素点击）。
- **落地准确率**：87%（104/120）。
- **下一步决策与原决策的一致率**：

| 条件 | 一致率 |
|---|---|
| A：真实截图 + 完整历史（模型自身随机波动的基准） | 87% |
| B1：图里存的截图 + 缺最近一条 summary | 66% |
| B2：图里存的截图 + 完整历史 | 68% |

- **初步结论**：掉点几乎都来自截图。图里存的截图来自别的时刻、别的任务，列表条目、已填的值、日期都不同。少一条 summary 只掉约 2–3 个点。

## 已踩过的坑（必须遵守）

- **新 arm 注册**：在 `full_run.py` 里，用"在元组末尾追加"的方式注册（把 `"FULL42")` 替换为 `"FULL42", "FULL43")`），然后用 `ast.parse` 检查、再 `import` 检查一次。整体字符串替换曾两次弄坏文件。FULL41 / FULL42 专用的分支（`ARM in ("FULL41", "FULL42")`、`ARM == "FULL42"`）要逐个确认是否也需要包含 FULL43。
- **模拟器内的后台负载模型**（llama.cpp 跑 Qwen2-VL-2B，模拟端侧推理开销）必须加 `--cache-ram 0` 启动。否则 prompt 缓存会把内存吃光（进程涨到 3GB 以上），模拟器的无障碍服务会崩溃，界面信息变成全空，所有数据作废。
- **每个 episode 前检查**：无障碍服务是否在 `dumpsys accessibility` 的 Crashed services 里（在就重新启用），以及模拟器可用内存。`e2e_driver.py` 已有这些检查；界面信息为空的比例超过 20% 的 episode 会标为出错并重跑。
- **出错的 episode 不计入统计**，否则会被算成 0 次推理，造成虚假的加速。
- **统计步数**：只统计模型推理次数（`model_calls`）。图执行、app 启动等不算步数。
- **跳过 THINK 的写法**：要跳过 THINK，就在 assistant 开头预填 `action:`，这是模型不 THINK 时的自然开头。不要预填 `explain:`，那会扰动输出。
- **不要整体跳过 THINK**：离线测试显示，会 THINK 的步骤上去掉 THINK 后变差 27 步、变好 7 步；限制在 40 个 token 也会变差，所以不要整体跳过。
- **比较方式**：只比较同一次运行里交错跑的组，跨天、跨运行的数字不可比。
- **其他**：不要 `rm -rf`，旧数据挪到 `aborted/` 下；不要提交 `logs/` 和 `exports/`；不要用 `uiautomator dump`；停止运行时要杀掉子进程（`full_run.py`），并用 `pgrep` 确认。
