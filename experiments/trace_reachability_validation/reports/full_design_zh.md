# MobileExplorer 完整设计：每个模块的动机与技术设计

> 只保留有实测动机的模块；每条动机都标注了出处（本目录或 `runtime_graph_study` 的分析文件）。完整 AndroidWorld 实验结果见 `full_results_zh.md`。

## 总体思路
- **图**负责记住"在这个页面、这个任务阶段，agent 接下来做了什么，以及做了之后到哪一页"。
- **探索**只去补图中**下一步决策会用到、但还缺的那部分**。
- **推理增强**不经过 prompt，而是由系统直接**替模型执行已经验证过的步骤**，或**提前准备好下一次观测**。

实测上已经排除的做法：
- 把图或子页面信息写进 prompt：6 种形式加安慰剂对照，都没有净收益（Pilot B）；
- 深度 2 探索：第二跳回滚失败 40%（Phase II）；
- 坐标修正：没有可修正的错误（离线 0/25）；
- 已有轨迹的页面上做覆盖式探索：GX 组调用 +5%、耗时 +31%（同 app 序列实验）。

## G：图（全局、连续、只追加）

| 组成 | 动机（实测） | 技术设计 |
|---|---|---|
| 不可变转移日志 | 多次观测要能保留（3.4% 的动作有多个结果），匹配规则还会改，需要能重建 | 每条记录 = (源页, 动作, 目的页, 来源 agent/探索/跳步, 运行实例, 回滚结果, 证据路径)；节点和索引都从日志派生 |
| 两级页面身份 | 结构签名在跨变体时误拆 14/16；骨架签名会误合并不同的设置子页 | **layout 级**（activity + 列表外控件骨架）用于匹配和跨任务统计；**struct + content 级**用于验证到达页面和回滚是否成功 |
| 动作身份 | 坐标不稳定；列表行文字是运行时数据 | class、resource-id、content-desc、label 组成动作身份；带 rid 的列表行按"行族"合并，不使用坐标 |
| 续写计数（核心） | agent 的下一步主要由它自己以前的轨迹决定（同任务 70%，跨任务 40%）；只统计点击会丢失任务阶段，实测导致"保存后又点新增" | 对 (页面, 最近 ≤3 步上下文) 统计下一动作，**包括所有动作类型**（输入、滑动、提交、结束）；先用最长能匹配的上下文，匹配不到再逐步缩短 |
| 证据范围 | 不可逆动作若只靠跨任务证据，会把"编辑"当成"删除"之类；同任务证据可以安全地授权提交（GC 组调用 −15%，成功率不变） | 计数同时按"同任务模板"和"全部任务"两个范围统计；提交类动作只认同任务证据 |
| 边属性 | 跳步需要验证到达页面；回滚需要知道能否回退 | 记录后继页面分布（两级身份都记）、回滚方法与结果，以及不可恢复标记（slot、列表同族、app 三级） |

## E：探索（深度 1，model-free，在推理窗口内）

**目标**：只降低"接下来的决策要用到的那部分图"的不确定性，不追求覆盖率。

| 模块 | 动机（实测） | 技术设计 |
|---|---|---|
| E1 预测下一步的验证探测 | 按轨迹排序后，agent 的动作在模型返回前就探到 9/14 次（轮询 1/13）；预观测结果与真实一致 11/14；跨运行转移有约 2% 会变 | 当前页上续写计数的第一名，如果它在**本次运行**里还没被观测过，就探 1 次：同时验证这条边仍然成立，并拿到它的下一屏 |
| E2 空隙页面补图 | 跨任务时一半点击落在空隙页面（没有任何轨迹统计）；探索覆盖这些页面后，预测从 8% 升到 24–42% | 只在空隙页面上，按屏幕顺序探最多 3 个未观测的安全出边，把这个页面接进图里 |
| 安全约束 | 回滚失败会污染 agent 的状态（深度 2 时 14/18 个 episode 中止） | 沿用 deny-list 和回滚梯子；一旦回滚失败，本 episode 停止探索，并重新观测、重新请求模型；不可恢复的控件写入记忆，跨任务生效 |

## R：用图增强推理（不经过 prompt）

| 模块 | 动机（实测） | 技术设计 |
|---|---|---|
| R1 验证过的跳步 | 跳步能减少 9%（只用导航）到 15%（加同任务提交）的模型调用，成功率不变 | 当前上下文的主导下一动作满足门槛（支持次数 ≥2、占比 ≥0.8），就沿主导链连续执行，最多 4 跳；每跳执行后检查到达页面是否等于历史后继页面，不一致就回退并交还模型 |
| R2 预观测复用 | 每次命中可省约 1.4 s 的动作后等待 | 模型选中的正是本窗口探过的动作时，执行后不做固定的 1 s 等待，直接比对页面；与探测到的下一屏一致就直接进入下一步 |

## 指标
- **任务指标**：成功率；成功 episode 的步数和模型调用。
- **机制指标**：
  - 跳步步数，及其中同任务提交的占比；
  - 跳步被拒绝的次数；
  - E1 / E2 的探测数，以及被 agent 实际用到的次数；
  - 回滚失败与重新请求次数；
  - R2 复用命中次数。
- 成功率的噪声：同一配置在 26 个 episode 上可相差 ±4。因此主要依据成对比较和机制指标。

## 修订版 FULL2（由完整 AndroidWorld 结果直接得出，不再单独做消融）

| 改动 | 依据（FULL 的完整实验） | 新做法 |
|---|---|---|
| 去掉在线 E2 | E2 共 358 次探测，只有 17 次被用上（5%）；123 次回滚失败后的重新请求大多来自它；第 2 轮 13 个"只有 BASE 成功"的任务中，7 个与回滚失败有关 | 在线只保留 E1：每步最多探 1 次轨迹预测的下一步。空隙页面补图改到任务之外的空闲时段离线做（尚未实现） |
| 提交类跳步改为"确认模型自己的意图" | 用同任务证据跳过 Delete → Yes，在"相对日期"类任务里删错了对象：同任务的历史证据也带参数 | 只有当模型**上一步刚亲自点了**提交类动作，紧接着出现的确认（OK / Yes / CONFIRM 等）才自动执行，并且只限链上的第一跳。意图来自模型本身，不依赖历史里的参数 |
| 提交跳步写入 agent 历史 | 提交无法撤销；如果执行后不写入历史，模型不知道这一步已经发生 | 提交跳步无论验证结果如何都记为已执行，并写入历史；验证不一致只用来停止后续跳步 |
| 不变 | 导航跳步按骨架签名验证；E1；预观测复用 | — |

FULL2 与已有的 BASE 两轮使用完全相同的 seed，按配对比较。

## 修订版 FULL3（由 FULL2 的部分结果直接得出）

| 改动 | 依据 | 新做法 |
|---|---|---|
| 跨任务跳步改为"模板一致" | FULL2 中 Markor 删除类任务被跨任务**多数**证据带去点 "Create new file"：多数票会把占比最大的任务模板的流程强加给其他模板 | 在当前 (页面, 上下文) 下，按任务模板分别统计主导下一动作；只有 **≥2 个模板的主导动作完全相同** 时才允许跨任务跳步。只有一个模板有证据时，按同任务门槛（n≥2、占比≥0.8）判断 |
| 跨任务跳步要求 agent 已"表态" | 任务入口处各模板分叉最大（跨任务 top-1 为 0%） | 跨任务跳步还要求：匹配到的上下文阶数 ≥1，且 agent 在本 episode 已做过非 open-app 的动作 |
| 不变 | — | E1 + 预观测复用；无在线 E2；提交只作为"模型刚亲自点了提交"后的确认，只限第 1 跳，并写入历史 |

## 修订版 FULL4（由 FULL3 完整结果直接得出）

| 改动 | 依据 | 新做法 |
|---|---|---|
| 跨任务证据不再授权执行 | FULL3 中有导航跳步的 episode：只有 FULL3 成功 2 个 vs 只有 BASE 成功 7 个，7 个全是 Calendar 的"月视图 → New Event"跨任务跳步。图只记录成功的 episode，失败模板不留证据，"模板一致"有幸存者偏差 | 跨任务计数只用来给 E1 探测排序（探测可回滚）；执行类跳步只认同任务证据，以及"模型刚亲自点了提交"之后的确认 |
| 跳步记录来源 | 之前的日志无法区分同任务 / 跨任务跳步 | 每个跳步记录 `scope` 字段 |

## FULL4 的结果对设计的含义
- 安全的跳步只能依赖同任务证据，但同任务门槛（n≥2）在两轮设定下几乎永远达不到：每个任务只有 1 条历史。FULL4 第 2 轮只执行了 9 步跳步。
- 小缺口：提交确认本应只由"模型刚亲自点了提交"来授权，FULL4 却也要求同任务证据，因此第 1 轮的确认跳步变成了 0 次。下一版应当去掉这个依赖。
- 下一版的推理增强应当转向**同一 episode 内**的流程复用：它不依赖跨运行历史，仓库已有实测 −5.5 步。跨运行的图只负责给 E1 排序和记录安全事实。

## 修订版 FULL5（推理增强改为 episode 内流程复用）

| 模块 | 动机 | 技术设计 |
|---|---|---|
| R3 实体流程复用（新增，主体） | 跨运行的证据来得太晚（FULL4 只执行了 9 步跳步），跨任务证据有幸存者偏差；多实体任务在一个 episode 内对每个实体重复同一流程（仓库已有实测：触发的任务省 5.5 步，成功率不变） | **实体**：模型点过的行（cls+rid 相同的可点击节点）里，作为完整词组出现在 goal 中的文字，不需要额外的模型调用。**模板**：从模型的实体点击开始，到模型自己执行的下一个提交之前；中间只允许非实体的元素点击。**触发**：回到同一 activity，同族的实体行在屏幕上，且没有未完成的实体。按 goal 顺序，下一个未完成实体必须可见，否则不触发（不跳过任务顺序）。**执行**：替换实体行后按模板执行，每跳按 activity 验证落点，不一致就停止。**永远不按提交键**，由模型按，模型的提交才关闭这个实体；每个实体只复用一次。每一跳都写入 agent 历史 |
| 提交确认 | FULL4 把确认也绑到同任务证据上，确认跳步变成 0 次 | 模型刚亲自点了提交、紧接着出现对话框按钮时，只在第 1 跳确认，不需要同任务证据；按哪个按钮仍取图中的第一名 |
| 跨运行跳步 | 同 FULL4 | 只认同任务证据 |
| E1 / 预观测复用 | 不变 | — |

冒烟测试（seed 30）：RecipeDeleteMultipleRecipes 模型调用 14→10，ExpenseDeleteMultiple 11→9，都成功；单实体任务 MarkorDeleteNote 不触发复用。
