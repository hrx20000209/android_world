# MobileExplorer 当前设计（FULL9，2026-10-15）

> 本文整理当前实现的完整设计：每个模块的动机、技术做法、实测依据和当前状态。
> - 代码：`scripts/full_run.py`（主循环，臂 `FULL9`）、`scripts/full7.py`（卡住规则、首次启动、启动折叠、提交确认）、`scripts/full9.py`（函数执行、探索排序）、`scripts/proc_replay.py`（任务内流程复用）；以及 `../runtime_graph_exploration/scripts/fgraph.py`（goal 解析、函数抽取、函数库）和 `memory.py`（不可变观测图）。
> - 历史实验与结论见 `full_design_zh.md`、`full_results_zh.md`，以及 `../runtime_graph_exploration/reports/*.md`。

## 0. 一句话
**图记住"做过什么、做了会怎样"；探索往图里补"没做过的会怎样"；推理增强只做两件事：替模型执行有授权的步骤，或在推理前用图把确定的操作直接做掉。** 跨任务的知识以"函数"的形式复用：图上带参数槽的子路径，参数由当前 goal 填入。

## 1. 每一步的执行顺序（推理前 → 推理中 → 推理后）

```
观测当前屏幕
  ├─ [推理前] 0. 启动折叠：第 0 步在桌面，goal 点名了 app → 系统直接打开（不计步）
  ├─ [推理前] 1. 卡住规则：同一导航控件连续 3 次无效 → 系统按一次返回（计 1 步）
  ├─ [推理前] 2. 函数执行：图中有授权的函数可用 → 替换参数后执行，停在提交前（整段计 1 步）
  ├─ [推理前] 3. 首次启动处理：任务 app 的引导页 → 系统点 skip / next / done（整段计 1 步）
  ├─ [推理前] 4. 提交确认：模型上一步刚亲自点了提交，且现在是纯确认框 → 点确定（计 1 步）
  ├─ [推理前] 5. 任务内流程复用：模型已对第 1 个对象示范过 → 对下一个对象照做（整段计 1 步）
  ├─ [推理前] 6. 同任务跳步：同模板历史中至少出现过 1 次的导航 → 逐跳验证执行（整段计 1 步）
  └─ 否则：模型推理（计 1 步）
        推理期间并行探索 1 次（E1 验证预测，或 FX 扩展图），回滚并验证
推理后：执行模型动作；记录效果（页面有没有变）；模型点了提交 → 更新记录进度、抽取本任务新函数
```

**记步规则**：
- 一次模型推理计 1 步；一段系统连续执行的多跳路径（函数、流程复用、跳步、首次启动）也只计 1 步；启动折叠不计步，模型在同一个计数步里看 app 的第一屏。
- 环境中实际执行的动作数另外记为 `env_actions`。

## 3. 函数：图上带参数槽的子路径（跨任务复用的核心）

### 3.1 goal 解析（`fgraph.parse_goal`）
把 goal 拆成**参数**和**操作词**：

| goal 形式 | 例子 | 解析结果 |
|---|---|---|
| 表格 | `name\|amount_dollars\|category_name\|note` + 多行记录 | 字段 = 表头，每行一条记录 |
| 键值块 | `Recipe: X` / ` description: ...` | 字段 = 键，`Recipe:` 开启新记录 |
| 行内键值 | `First Name: Ivan, Last Name: Adams, Phone: ...` | 字段 = 键 |
| 引号值 | `the title 'Catch up on Annual Report'` | 字段 = 引号前最后一个内容词（title） |
| 冒号后的列举 | `Delete the following expenses ...: A, B, C.` | 字段 = `enum:` + 冒号前的内容词，每项一条记录 |
| 文件名、电话号码、`message: ...` | `copy_cool_snake.txt`、`+18490934066` | 字段 = file / number / message |

- **操作动词**：goal 中第一个动作词，同义词归一（create/new → add，remove → delete …）。
- **操作词**：去掉参数后剩下的内容词，用于探索排序。

### 3.2 函数抽取（`fgraph.extract`）
从成功轨迹中，按"提交"（Delete、Save、OK 等）切段。每段是一条子路径：入口屏幕 → 一串动作 → 停在提交前。动作分三类：
- `nav`：普通导航点击，记录控件身份；
- `slot_click`：点的元素包含 goal 中某个参数值，例如列表行 "Tuition Fees"，记录字段名和行族；
- `type`：输入的文本等于 goal 中某个参数值，记录字段名和输入框身份（rid，或屏幕上第 k 个输入框）。

只有包含至少一个参数槽的段才成为函数。所有成功 episode 的函数一次性抽取到 `graph/function_cache.jsonl`（共 318 个），按模板打标签；运行时按留一模板过滤。

### 3.3 授权与执行（`full9.FuncExec`）
一个函数可以用于当前任务，必须同时满足：
1. **操作动词一致**（add / delete / send …）；
2. 函数需要的**每个字段**都能在当前 goal 里找到值；
3. 函数入口的 activity 等于当前屏幕的，且第一步的目标在屏幕上找得到。

执行时：
- 参数取当前 goal 中**下一条未处理记录**的值，按 goal 顺序，每条记录最多由函数尝试一次；
- 逐跳执行，每跳先验证目标存在，输入后检查输入框；
- 停在提交前，提交由模型完成；模型提交后，记录推进到下一条；
- 整段计 1 步，每个动作以 `[graph] ...` 写入模型可见的历史。

函数来源三种：
- 同 app 其他任务（历史，留一模板）；
- 本任务已完成的部分：模型每次提交后，从本 episode 抽取新函数；
- 探索：探测得到的导航边进入图，用于把当前屏幕连到函数入口（连接逻辑尚未接入执行器，见第 9 节）。

### 3.4 离线回放（`runtime_graph_exploration/scripts/fgraph_offline.py`）
- 在 BASE 第 1 轮轨迹上，函数触发 165 次，预测 583 个动作，和模型实际动作逐步一致的只有 53 个（9%）。
- 但这个指标只说明"函数和模型走法不同"，不说明函数错。回放里也没有记录"这条记录已经处理过"，同一页面会反复触发。
- 正向信号：ExpenseAddMultiple 里，从 ExpenseAddSingle 抽出的"添加支出"函数，在第一条记录上 6 步对上了前 4 步，包括 name、amount 的输入。

## 4. 探索（推理期间，不调用模型）

| 模式 | 何时 | 选什么 |
|---|---|---|
| E1：验证预测 | 图对当前屏幕和上下文有下一步预测，且这个控件本次运行还没观测过 | 预测的控件 |
| **FX：扩展图**（FULL9 新增） | 没有可验证的预测 | 当前屏幕中，图里没观测过的安全、非列表行控件，排序如下 |

**FX 的排序**（只排序，不设阈值）：
1. 与 goal **操作词**的 TF-IDF 余弦相似度，高者优先。操作词不含参数，因为 goal 里 TF-IDF 最高的词往往是参数（对象名、数值），它们回答"对谁"，而不是"用哪个功能"。
2. 跨 app 的通用程度，出现的 app 越少越优先：通用控件（More options、Search …）排最后。
3. 屏幕顺序。

**安全**：
- 沿用 deny-list（Delete、Save、Send 等）；跳过已知不可退回的控件族。
- 回滚失败只封禁**那一类控件**（同一 app 内同一身份），第 2 次失败才停止本局探索。
- 之前 116 局里有 16 局在一次失败后整局停探，FULL8 中这类窗口占了 11%。

**为什么要改**：FULL8 中 1081 个推理窗口里，55% 因图没有预测而不探，只有 7% 做了 E1。探索只在验证预测，几乎没有扩展图。

**用处的记录**：探索得到的边是否后来被函数入口路径或模型走到，需要单独计数（统计脚本尚未写）。

## 5. 其余模块

| 模块 | 做法 | 动机 / 实测 |
|---|---|---|
| 启动折叠（图复用） | 第 0 步在桌面，goal 点名的 app（最早出现、最长别名）的包在图中出现过 → 推理前直接启动，不计步，等界面稳定后截屏 | FULL8：触发 94 次，每次省 1 步 1 次调用，是步数下降的主要来源。v4x 文档同样把它列为最大来源 |
| 提交确认 | 模型上一步亲自点了提交，现在出现**纯确认框**（只有提示文字和 button1/2/3，没有列表、选项、输入框）→ 点 button1 | FULL8 不限对话框类型：SaveCopyOfReceipt 的"Copy to"文件夹选择器被直接 OK，选错目录后循环，FULL9 加了纯确认限制 |
| 任务内流程复用 | 模型对第 1 个对象完整示范后，对 goal 中**并列列出**的下一个对象照做，停在提交前 | FULL5：触发的 9 个 episode 全部成功，调用 −19%。列举限制修掉了 MarkorMoveNote 的误触发 |
| 同任务跳步 | 同模板历史中出现过 ≥1 次的导航，逐跳验证 | 单轮下基本不触发 |
| 首次启动处理（独立模块） | 任务 app 的 activity 名含 intro / onboard / welcome / tutorial / wizard，且屏幕在图中未出现过 → 依次点 skip / done / get started / got it / start / continue / next；桌面不处理 | 引导页实验中，BASE 和轨迹注入都是 0/6；FULL8 误处理过桌面的欢迎导览，FULL9 已排除 launcher |
| 卡住规则（硬编码） | 只统计**安全的导航控件**是否无效，输入框、开关、选值、提交不算；同一控件在同一屏幕连续 3 次无效 → 按一次返回；**不再注入任何提示** | FULL8 的 24 次卡住提示多为误判（点输入框、点 Save），还有推荐"Change photo"导致失败的情况 |
| SMS 角色重置 | 每个任务开始前，把 SMS 默认应用重置为 Simple SMS Messenger | 已知的模拟器环境漂移，会让所有 SimpleSms 任务失效 |

**不再使用的做法**（实测为净负或无效）：
- 跨任务的单步导航跳步：有幸存者偏差，Calendar "New Event" 造成 7 vs 2 的损失；
- 任何形式的 prompt 注入：单元素推荐只有约 50% 正确，模型自己约 90%；高亮框模型不响应；函数路径注入无效果；卡住提示净负；
- 在线覆盖式探索（E2）。

## 7. 已有结果（单轮 seed 30）

| 版本 | 成功 | 平均步数 | 成功任务平均步数 | 两边都成功的任务上（vs 4B_2）的步数 |
|---|---|---|---|---|
| 4B_2 | 54/114 | 10.75 | 7.85 | — |
| BASE（同框架） | 51/114 | 10.05 | 7.41 | — |
| FULL7（无启动折叠，多跳逐步计数） | 60/114 | 10.05 | 7.83 | 7.36 → 7.34 |
| FULL8（+启动折叠、多跳计 1 步、确认、n≥1 跳步） | 53/114 | **9.61** | 7.79 | **7.63 → 7.24**（调用 6.90） |

- FULL8 步数下降主要来自启动折叠。
- FULL7 比 BASE 多出的成功，逐个看几乎没有机制介入，更可能是运行波动或跨时段漂移。
- FULL8 的成功率被两个设计缺陷拉低：确认了文件夹选择器、误处理桌面欢迎导览。FULL9 已修正这两点。

## 8. FULL9 冒烟测试（seed 30，2 个任务）——发现的问题

| 任务 | 结果 | 发生了什么 |
|---|---|---|
| ExpenseDeleteMultiple | 失败（13 步，12 次调用；BASE 能成功） | 函数正确地点了第 1 条 "Tuition Fees"，模型删除后，函数却选了第 3 条 "Reimbursements"，任务内流程复用又点了已删除的 "Tuition Fees"，两个机制相互冲突 |
| ExpenseAddMultiple | 失败（20 步，19 次调用） | 函数点了 "+" 和 Name 输入框，但**输入这一步没执行**就停了；模型随后重新打开 app，自己完成了第 1 条记录。之后每条记录都重复"点 + → 点 Name → 停" |

**原因与修正计划**：
1. **记录进度推进两次**：删除流程中，btn_delete 和 CONFIRM 都被识别为"提交"，每个对象推进了 2 条记录。改为：一条记录只在其函数（或模型自己的流程）完成后推进 1 次；同一条记录的确认对话框不重复推进。
2. **函数和流程复用冲突**：FULL9 中两者都在推理前触发。改为：函数执行优先，同一记录不再由流程复用处理；或者在 FULL9 中用函数统一取代流程复用，因为任务内抽取已经覆盖了流程复用。
3. **输入框定位失败**：GELAB 的输入动作常常不带坐标，直接输入到当前聚焦的输入框，所以抽取时没有记录输入框身份。改为：
   - 抽取时，用前一步点击的输入框作为该次输入的目标；
   - 执行时，如果前一步刚点了输入框，就直接输入到聚焦框。
4. 函数的第一步有时是无标签的返回按钮（`E|ImageButton|||`）。抽取时应去掉段首的"返回"类导航。
